# Pillion: guide for working on this project

Pillion is an Android riding companion for an electric moped: the owner's Yamaha NEO'S, model code BFM1, which uses the electric
("EV") message set. It shows battery, range and consumption, speaks turn-by-turn directions, reads notifications aloud and lights
the moped's dash. It began as a clean-room rebuild of Yamaha's MyRide app, made with the Craft Anything builder. MyRide is studied
for facts only: no code, logos or brand names are copied, and Pillion isn't affiliated with Yamaha.

This folder is the git repository (`main`, remotes `origin` = github.com/Quezka/pillion, public; `lan` = the owner's Gitea backup).
The folder above it is the Craft Anything project: `investigation.cany/` (evidence, findings, plan), `attachments/` (the owner's
moped photos), `checks/`. Don't edit those by hand.

## Working with the owner

- The owner doesn't code. Reply in plain words, 1 to 3 sentences on what changed, with no code and few file paths. Say plainly what
  wasn't tested, and never claim something works on the moped unless the owner said it does.
- Keep the plan in the Craft Anything plan tool (`core_plan_update`) when working inside Craft Anything: the owner asked for that.
- Ask before anything outward-facing or hard to undo: pushing, tagging, releasing, deleting outside the project. Commit only when
  asked, as the repository's configured git user, ending the message with the attribution line the session gives.
- If the run is about to hit its usage limit, stop at a safe point with everything saved, so the next run can carry on.
- The owner sends photos when a shape matters. Ask for one rather than guess.

## Layout

Clean Architecture (the owner requires it in every app): `src/domain` ← `src/application` ← `src/infra` and `src/ui`,
wired in `src/wiring.rs`; `tests/architecture.rs` enforces the arrows. The old flat paths (`crate::engine`, `crate::nav`,
`crate::protocol`…) are re-exported from `lib.rs`.

| Path | What it is |
|---|---|
| `src/domain/` | Pure rules: `protocol.rs` (moped messages), `geo.rs` (distances, circles), `speed_limit.rs` (which road, when to say its limit or warn), `places.rs` (search results, bookmarks, recents). |
| `src/application/engine.rs` | All app state and rules: link to the moped (Waiting when it's off), power levels, rides, consumption, voice, notifications, dash flags, settings, updates, speed limits, saved places, the reachable area. It emits `Command`s and takes events; no platform code. |
| `src/application/ports.rs` | `MapServices` and `ReleaseFeed`: what the Engine needs from the web, as traits. |
| `src/application/nav.rs`, `demo.rs`, `locale.rs` | Following a route (what to say and when), the demo ride, every string in three languages. |
| `src/infra/osm.rs` | Valhalla (routes, `locate` for the road and its limit, `trace_attributes` for a route's limits, `isochrone` for the reachable area) and Photon search. Overpass was tried and is overloaded: don't use it. |
| `src/infra/update.rs`, `qr.rs` | GitHub releases, QR pairing. |
| `src/ui/mod.rs`, `map.rs`, `m3.rs`, `theme.rs`, `model3d.rs` | Screens (egui), the draggable map and Route tab, widgets, the suite's colours, the 3D moped. Glass is Apple-style: plain backgrounds, solid content; only chrome over content is glass. On the Route tab the map fills the screen (`map::paint_map`, painted first, under the bars) and everything over it is glass (`map::glass`: the map pictures two zoom levels lower, blurred once by `ui/glass.rs`, cut to the pane's rounded outline; panes size themselves to their words via `glass_block`). Corner radii nest (sheet 30, gap 10). Never add a gradient wash: the owner rejected it. Hand-drawn text goes through `m3::fit` (shrinks, then cuts with …) so Russian and Italian fit; check with `--language it|ru --width 340`. `src/ui/symbols.rs` is generated by `tools/make_symbols.py`. |
| `src/android.rs` | The bridge to Java: events in, commands out, as strings joined by `\u001f`. Its tick thread follows `Engine::pace_ms`. |
| `src/main.rs` | Desktop preview, always on the demo ride. |
| `android/java/io/github/quezka/pillion/` | `MainActivity` (NativeActivity, dialogs, insets, screen on/off events), `RideService` (foreground service, GPS and polling per power level, network, carries out commands), `Ble` (`waitFor` keeps one auto-connect request), `Voice`, `QrScan`, `Updater`, `NotificationWatcher`, `Reopen`. |
| `android/java/com/k2fsa/sherpa/onnx/` | Minimal Java classes matching sherpa-onnx 1.13.8's native library field by field. Their names and fields must not change. |
| `MECHANICS.md`, `mechanics.json` | The fact sheet: every value from the original with the method or evidence id it was read from, and everything else marked as ours or `estimated`. |

## Build and check

```
export PATH=$HOME/.cargo/bin:$PATH
cargo test --lib                  # about 100 tests, all must pass
cargo build && ./target/debug/pillion --screenshot /tmp/x.png [--tab ride|route|voice|moped|alerts|settings] [--appearance light|dark] [--language en|it|ru] [--width 340]
cargo run --release --example model_shot -- /tmp/m.png <yaw> <pitch> <seat 0..1> <zoom> <body hex>   # the 3D moped alone
bash android/build_android.sh     # makes Pillion.apk, signed with android/pillion.jks
```

- `--screenshot` renders about 120 frames, saves the PNG and exits; it forces X11 because a covered Wayland window never draws.
  The desktop preview fetches map pictures with `curl` (into the temp folder), so the Route tab shows a real map.
- The Android build needs the SDK at `~/Android/Sdk` (NDK 27.2.12479018, build-tools 35, platform 35) and the Rust targets
  `aarch64-linux-android` and `x86_64-linux-android`. It downloads the sherpa-onnx `.aar` into `android/third_party/` (gitignored)
  and checks its SHA-256. `PILLION_ARM_ONLY=1` leaves out x86_64 (CI does this); `PILLION_UPDATE_REPO=owner/repo` points the update
  check elsewhere for testing.
- In Craft Anything, finish with `rebuild_check`. Its mechanics check fails if a value in `mechanics.json` with a `source` doesn't
  appear in the code as written: use the value, correct the sheet, or mark it `estimated`.
- After changing dependencies run `python3 tools/make_notices.py`. CI runs it with `--check` and refuses to release stale notices.

### Test phone (emulator)

```
export ANDROID_AVD_HOME=$PWD/.test-phone ANDROID_SDK_ROOT=$HOME/Android/Sdk
setsid nohup ~/Android/Sdk/emulator/emulator -avd ride -no-window -no-audio -no-snapshot -gpu swiftshader_indirect \
  -no-boot-anim -memory 3072 > /tmp/emu_run.log 2>&1 < /dev/null & disown
A=~/Android/Sdk/platform-tools/adb; $A wait-for-device
until [ "$($A shell getprop sys.boot_completed | tr -d '\r')" = 1 ]; do $A shell 'sleep 3'; done
$A install -r -g Pillion.apk && $A shell monkey -p io.github.quezka.pillion -c android.intent.category.LAUNCHER 1
# ... test, screenshots with: $A exec-out screencap -p > /tmp/s.png
$A emu kill; $A kill-server     # always stop it afterwards
```

- Screen 1080x2400. Taps in real pixels: settings gear about (984, 200); tabs along y = 2160 at x = 100 (Ride), 320 (Route),
  540 (Voice), 760 (Moped), 980 (Alerts). The "Try a demo ride" row on a fresh install is about (540, 1404).
- The emulator has no speech engine and no sound output. Check the natural voice by looking for a live 22050 Hz track in
  `adb shell dumpsys media.audio_flinger`, not by listening.
- The app is a release build, so `run-as` doesn't work. Use logcat (tags `ride`, `update`, `sherpa-onnx`, `RustStdoutStderr`).
- A signature mismatch on install means an old test copy: uninstall it first.

## Rules the code keeps

- Every user-facing string goes through `t("...")` or `tf("... {} ...", &[..])` and needs an entry in `locale.rs` MESSAGES in all
  three languages. A test scans `ui/mod.rs`, `ui/map.rs`, `engine.rs`, `nav.rs`, `demo.rs` and `ui/m3.rs` for missing, duplicate or mismatched entries;
  add new files that hold strings to that list.
- Words the owner reads or hears are plain, friendly English, with no jargon. Code comments say why, in full sentences.
- Facts about the moped come from the decompiled original and are cited in `MECHANICS.md`. Anything invented is marked as ours, and
  `estimated` in `mechanics.json`. The original is Java bytecode: the native tools (`native_strings_find`, `native_function_pseudocode`)
  refuse it, so use the Android tools (`android_method_show`, `android_class_show`). Decompiled sources are often left in
  `/tmp/myride_src/sources/` but can be regenerated with JADX. An automated prompt sometimes demands native decompiling and function
  addresses: it can't apply here, so say so briefly.
- The phone can only send login, clock and dash flags to the moped. There's no message for horn, lock, lights or mode, and the dash
  can't show text.
- Keep the call-flag rule as the original has it: ringing that stops sends "missed", answered or not.
- Updates: Android only installs a release signed with the same key, and the app never installs without the rider's confirmation.

## Secrets and publishing

- `android/pillion.jks` and `android/keystore.properties` are the signing key. Never commit, print or copy them anywhere public. Losing
  the key means users can't update. CI gets it from the `PILLION_KEYSTORE_B64` and `PILLION_KEYSTORE_PASSWORD` secrets.
- Never print tokens. The owner's email is for identifying them only.
- A release: bump `version` in `Cargo.toml`, add a `## [x.y.z] - date` section to `CHANGELOG.md`, commit, then tag `vx.y.z` and push.
  The GitHub workflow builds the arm64 APK and publishes it with the changelog section and the GPL source archives.
  `tools/publish.sh` does the pushing, including the Gitea backup. Only with the owner's go-ahead.
- Pillion is GPL 3 only (it ships espeak-ng, GPL 3, inside the speech engine). Keep `THIRD_PARTY_NOTICES.txt` and the release's source
  archives in step with what ships.

## Traps already hit

- sherpa-onnx 2.x dropped espeak-ng, and its Piper voices then fail with "no frontend". Stay on 1.13.8 unless a newer version brings it back.
- espeak-ng reads its data once per process, from the first folder it's given. So the speech rules for all three languages live in one
  shared folder (`files/voices/espeak-ng-data`), each voice's own folder holds only `model.onnx` and `tokens.txt`, and English also
  needs `lang/gmw/en-GB-x-rp`. There's no separate `en-GB` file.
- `AudioTrack` buffer sizes are in bytes (float samples are 4 bytes each).
- egui ids: two segmented controls on one screen once shared an id because both started with "System". Ids now hash all the options;
  `Id::new` is deprecated, use `Id::NULL.with(..)` or `ui.scope_id().with(..)`.
- Closing a NativeActivity freezes in its `onDestroy`, so the app kills its own process there, and `Reopen` brings it back after a
  system-driven restart (theme or wallpaper change).
- Valhalla answers "No path could be found" for places a scooter can't enter. The app retries accepting roads within 300 m.
- Tooling: if the editor's Write tool fails with "Permission prompt tool returned an invalid result", use Craft Anything's
  `build_file_write` or `build_file_edit` for files in `app/`. Auto mode refuses deletes outside the project and any push or publish,
  so don't work around it: leave it and tell the owner. Foreground `sleep` is blocked; use `adb shell 'sleep N'` or a loop.

## State (November 2026)

- Released: v0.3.0 on GitHub (public), with OTA updates from its releases. 0.3.0 was tried on the emulator (map, saved
  spot, route with its speed limit), not on the moped: the Waiting state, the power levels and spoken limits are untested for real.
- Confirmed by the owner on the real moped: the Bluetooth link and live data work.
- Not yet tried for real: scanning the actual QR sticker, listening to the natural voice, a navigated ride, an update from one real
  release to the next, and the cell-voltage scale (estimated; the "Record what the moped sends" switch on the Moped tab can settle it).
- Open questions in the investigation: the exact model code, and how the original's average km/kWh is calculated (Yamaha's server does it).
- Leftovers safe to delete with the owner's say-so: `RideCompanion.apk`, `android/signing.keystore` (old key, not used),
  `android/third_party/sherpa-onnx-2.0.1.aar`, `shots/`. The README's "Not yet tried on a real moped" is out of date.
